# Worker access to operator controls

Distributed controllers require the existing private controller bearer token for every non-GET/HEAD/OPTIONS request beneath /api. The token is read from Controller.TokenFile at dashboard startup, never rendered or sent to the browser. Server-side UI HttpClients add it only to same-origin API mutations. External URLs and read requests receive no token. Missing/short token fails startup; unauthenticated mutations return401 before endpoint execution. Legacy non-distributed hosts retain their existing private-local behavior.

The installer foundation also includes forge-worker-public-egress, selecting only app.kubernetes.io/name=forge-worker. It permits TCP/UDP53 to kube-system CoreDNS pods and public IPv4/IPv6 destinations, excluding private, loopback, link-local, shared-address and reserved ranges. GitHub, OpenAI and public Azure SQL remain eligible; a private Azure endpoint needs a separately reviewed destination exception. No broad cluster/LAN exception is added for DNS.

These are complementary boundaries. The anonymous Blazor Server UI remains trusted on the private operator network and can perform authorized server-side actions. Therefore worker isolation must be qualified against the WHOLE dashboard: ClusterIP, controller PodIP and every LAN/node proxy exposure, not only /api. Kubernetes notes local-node and NAT implementation caveats, so manifest shape alone is not evidence of enforcement. No claim of an adversarial sandbox is made: workers still share a PVC and have other workload database permissions.

Before releasing work gates, root applies the reviewed foundation policy and qualifies a new worker-labelled, non-hostNetwork, tokenless pod. The probe must show cluster DNS plus public GitHub/OpenAI TCP443 and actual read-only worker Azure SQL access succeed, while dashboard ClusterIP8080, controller PodIP8080 and known node/LAN dashboard routes fail. No model request is required. Also verify ordinary browser mutations work and direct API mutations without token return401. Existing CLI operator helpers must read the private controller token and add Authorization on mutations; no unauthenticated endpoint exemption is provided.

If any whole-dashboard path remains reachable, keep gates held and report it; do not claim that the API bearer guard alone closes the Blazor proxy path. Do not widen private egress to repair public connectivity. Existing connections and additional additive NetworkPolicies may change enforcement and must be considered in live evidence.

Primary references: https://kubernetes.io/docs/concepts/services-networking/network-policies/ and https://docs.k3s.io/networking/networking-services . K3s uses its embedded network policy controller by default; an installation with that controller disabled cannot rely on these rules.
